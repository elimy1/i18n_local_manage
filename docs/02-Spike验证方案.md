# Spike 验证方案（M0，2 周）

> 目的：用**可测量的证据**回答"这个产品能不能做、值不值得做"，而不是先写完再验证。
> 产出：一份 Go/No-Go 决策备忘 + 可复用的评测脚本 + 3 组改写前后对照。

---

## 1. 要回答的 5 个假设

| # | 假设 | 判定阈值 | 不过怎么办 |
|---|---|---|---|
| **H1** | 硬编码检测在高置信层足够准 | precision ≥ 0.90，recall ≥ 0.60（30 个文件标注集） | 收紧规则、只保留 CJK + 白名单属性；产品退化为"中文项目专用"仍成立 |
| **H2** | AST 改写不会破坏代码 | 语法通过 100%，`tsc --noEmit` 通过 100%，人工抽检语义缺陷 ≤ 5%（30 处） | 退回"只报告 + 手工确认单处"，砍掉批量 |
| **H3** | 性能可接受 | 3k 文件首次索引 ≤ 30s；单文件 ≤ 80ms | 引入 oxc/swc 做扫描，或改增量懒解析 |
| **H4** | 框架差异可被 adapter 吸收 | 第 3 个 adapter 接入 ≤ 3 人日，无需改 core | adapter 抽象错了，重设计接口再验证一周 |
| **H5** | 开发者愿意用 | 5 人试用，任务完成率 ≥ 80%，无需求助 | 交互模型有问题（可能应该做成"批量向导"而非 CodeAction） |

**H2 是一票否决项**。H1 不达标可以缩范围，H2 不达标则整个"自动改写"叙事不成立。

## 3. 评测方法

### 3.1 标注集

- 从 F1/F2/F3 各抽 **10 个文件**（随机 + 人工保证覆盖组件/页面/工具函数三类），共 30 个文件。
- 标注口径（写死在 `spike/labels/README.md`，避免中途漂移）：
  - **应提取**：用户可见的自然语言文案（含中文、英文句子、含变量的提示语）。
  - **不应提取**：日志、异常信息（可争议，统一归"不提取"）、className、样式、URL、纯符号/数字、key 本身、测试断言。
- 双人标注 5 个文件算一致率，Krippendorff's α < 0.8 就先统一口径再继续。

### 3.2 度量脚本

```
spike/
  scan.ts          # 输入仓库路径 → 输出 candidates.json
  labels/          # 人工标注（YAML: file, line, text, expect: true|false）
  eval.ts          # 对齐 candidates 与 labels，算 P/R/F1，按分数档位分组
  codemod.ts       # 输入候选 → 生成 diff（不落盘）→ 输出 patch
  bench.ts         # 索引耗时 / 单文件耗时统计
  report.md        # 自动生成的指标表
```

对齐规则：以 `(文件, 起始行, 归一化文本)` 三元组匹配，允许 ±1 行漂移（格式化差异）。

### 3.3 改写验证

1. 每个仓库选 **10 处高置信候选**自动改写（共 30 处）。
2. 检查：`tsc --noEmit`（TS 项目）/ `vite build` 通过；`eslint` 无新增错误。
3. 人工 review 30 处 diff，记录缺陷类型：
   - 作用域错误（hook 用在非组件）
   - 插值参数丢失/命名错
   - namespace 前缀错
   - 语义错（选错 key、复用不该复用的 key）
4. 指标：`语义缺陷率 = 缺陷数 / 30`。

### 3.4 性能基准

- 用 F3（最大）跑全量索引 3 次取中位数。
- 单文件：随机 50 个文件，测 parse+detect 耗时 P50/P95。
- 记录内存峰值（`process.memoryUsage().heapUsed`）。

## 6. Go / No-Go 判据

**Go（直接进 M1）**：H1 ✅ 且 H2 ✅ 且 H3 ✅
**条件 Go（缩范围进 M1）**：H2 ✅，H1 或 H3 有一项 ❌
→ 例：precision 只有 0.85 → 只在高置信层开放自动改写，中置信层只报告。
**No-Go（换方向）**：H2 ❌（改写不可靠）或 H4 ❌（抽象反复推倒）
→ 备选方向：纯"检测 + 覆盖率"工具（不做改写），或转向 CI 守门产品。

## 7. 已知的坑（提前写下来，省两天）

1. **`.vue` 的 template AST 与 script AST 是两套**，位置信息不同源，节点 offset 需要统一到原文件坐标。
2. **Babel 的 `start`/`end` 是字节还是字符**——是 UTF-16 code unit offset，和 `TextDocument.positionAt()` 一致，别自己转码。
3. **JSX 文本节点含实体**（`&nbsp;`）与换行缩进，归一化后要与源码 offset 分开保存，否则回写错位。
4. **模板字符串里的表达式**只能取源码切片，不要试图求值。
5. **worker_threads 在打包后路径会变**，`new Worker(new URL('./worker.js', import.meta.url))` 在 CJS 产物里需要单独 entry。
6. **`tsc --noEmit` 在大仓很慢**，Spike 阶段只在改动文件所在 project 跑，或直接用 `esbuild` 做语法级校验。
