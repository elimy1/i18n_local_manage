# M0 Spike 结果报告（H1–H5 与 Go/No-Go）

> 对应方案：[02-Spike验证方案.md](02-Spike验证方案.md) ｜ 上游规划：[01-技术规划.md](01-技术规划.md)
> 执行日期：2026-11-03 ｜ 全部数字来自本机实测，可复现（见 §9）

---

## 1. 一句话结论

**GO，但带三个前置条件。** 检测精度达标（阈值 0.55 时 P 91.3 / R 82.3），改写成功率 91%，语义缺陷率 3.75%（低于 5% 红线），性能比预算宽 30 倍；但**键命名质量是硬伤（72% 落到哈希键）**，且**句子碎片化**问题会让英文语序出戏——这两点必须在 M1 之前定方案，否则产品会"能用但不敢用"。

## 2. 实验设计（以及它和原方案的偏差）

| 项 | 原方案 | 实际执行 | 影响 |
|---|---|---|---|
| 语料 | F1/F2/F3 三个真实项目，含 1 个英文项目 | vben-admin（1495 文件，Vue3）、ant-design-pro（262 文件，React/Umi）、vercel/ai-chatbot（156 文件，Next.js） | 规模与异构度达预期；但都是"中文硬编码为主"的国内项目，英文项目只有 1 个 |
| 检测评估 | 分层抽样 + 人工标注 | 3 份语料共 258 条抽样标注（90/92/76），全部按 0.05 粒度扫阈值 | 样本量 OK；chat 只有 76 条，其 recall 63.3% 的置信区间较宽 |
| 改写验证 | 语法 + tsc + 语义抽检 | 后置语法闸全量跑；**未做项目级 tsc**（语料无依赖，装不全）；语义用 80 条人工抽检 + 3012 条全量启发式审计 | tsc 缺失是最大偏差：类型错误可能漏检 |
| 性能 | 3k 文件 <30s | 实测 1.5k 文件 1.0s | 结论稳健 |
| 可用性 H5 | 20 人任务测试 | **未执行** | 无用户数据，H5 仍为未知 |

其余偏差：所有改写都写在 `spike/out/rewritten/` 副本上，未触碰语料原文件；`@/i18n`、`@/i18n/react` 这两个模块是 spike 里的桩，真实项目里需要由扩展生成。

## 3. H1 检测精度：达标（阈值 0.55）

### 3.1 汇总（pooled，258 条标注）

| 阈值 | Precision | Recall | F1 |
|---|---|---|---|
| 0.30 | 66.8 | 91.5 | 77.3 |
| 0.45 | 72.1 | 91.5 | 80.7 |
| **0.50** | 88.2 | 85.1 | 86.6 |
| **0.55** | **91.3** | **82.3** | **86.6** |
| 0.60 | 95.1 | 82.3 | 88.2 |
| 0.70 | 96.7 | 82.3 | 88.9 |

- 目标 P≥0.90 / R≥0.60。**0.55 起达标**（P 91.3 / R 82.3）；0.50 时 P 差 1.8 个点。
- 精度断崖在 0.45→0.50（P 72.1→88.2）：说明打分刻度不连续，真实置信度更像"台阶"而非线性。产品里应暴露 0.45–0.55 的"待确认区"而不是单一开关。

### 3.2 分语料（阈值 0.5）

| 语料 | P | R | 说明 |
|---|---|---|---|
| vue-vben-admin | 90.5 | 90.5 | 中文为主，最稳 |
| ant-design-pro | 88.7 | 91.3 | 同上 |
| ai-chatbot（英文） | 82.6 | 63.3 | **英文裸字面量召回只有 63%**，因为基线分 0.25 |

→ 产品含义：中文项目可作为首发主打场景；英文项目要先解决"英文短标签 vs 技术字符串"的区分（Tailwind 类串、状态枚举是主要 FP 源）。

### 3.3 分 kind（阈值 0.5，pooled）

| kind | n | P | R | 读法 |
|---|---|---|---|---|
| obj-prop | 71 | 95.0 | 95.0 | 主战场，可靠 |
| jsx-attr | 23 | 95.2 | 95.2 | 可靠 |
| vue-attr | 6 | 100 | 100 | 样本少 |
| vue-text | 9 | 100 | 88.9 | 可靠 |
| jsx-text | 22 | 92.3 | 63.2 | 漏检多在短标签 |
| string-literal | 70 | 100 | **43.8** | 召回洼地（英文裸串基线低） |
| call-arg | 29 | 66.7 | 100 | 精度洼地（`t('key')` 包裹类） |
| template-literal | 25 | **30.0** | 100 | **精度洼地：插值模板** |

### 3.4 漏检归因

21 条漏检的真阳性**全部**归因 "(no negative reason)"——不是被负向规则误杀，而是**分数没够**。这排除了"规则打架"这一假设，直接指向基线分设计：裸字面量 0.25 太低。

### 3.5 四类系统性噪声（已写入产品默认策略）

1. **已翻译代码稀释召回**：`$t('authentication.terms')` 会进候选池，靠 `wrapped(-1)` 拒绝。vben 样本里 call-arg 17/17 全是这种。
2. **测试文件重度污染**：`__tests__/`、`e2e/` 里的 `it()` 标题、选择器、断言消息。必须默认排除（本 spike 最终排除了 vben 124 条、adp 48 条）。
3. **Tailwind/工具类串**：`cn('flex items-center ...')`，英文 TSX 的头号 FP 源（chat 76 条里 27 条）。
4. **SVG 资源**：Figma 导出的 `<svg>` 会产生上千条 id/fill 候选（vben `slogan.vue` 曾产出 3345 条）。整棵子树剔除后归零。

## 4. H2 改写正确性：达标（3.75% < 5%）

### 4.1 规模

| 语料 | 文件（有候选→改写） | 候选 → 应用 | 跳过 | 后置语法失败 |
|---|---|---|---|---|
| vben | 321 → 261 | 2586 → 2351（90.9%） | 235 | **0** |
| adp | 78 → 66 | 787 → 661（84.0%） | 126 | **0** |

跳过原因（vben / adp）：test-file 124/48、key-like 58/0、code-like 35/3、script-file 6/43、jsx-no-component-scope 0/29、technical-string 6/0、console-log 3/0、overlap 2/2。

### 4.2 语义缺陷抽检

- 人工抽检 80 条（各 40）→ 3 条缺陷（3.75%）：句子碎片（`发布在`、`万`）+ 1 条重复包裹。
- 全量启发式审计 3012 条改写 → 18 条候选（0.60%），人工复核后真正有问题的约 4–6 条（0.13–0.20%），其余是含引号/等号的中文文案被误报。

**结论：低于 5% 一票否决线，但缺陷不是随机的**——集中在"句子被切碎"和"技术字符串漏网"两类。

### 4.3 七个真实 bug（这是本次 Spike 最有价值的产出）

| # | bug | 症状 | 为什么危险 | 修法 |
|---|---|---|---|---|
| 1 | tagged template | `` css`...` `` → `cssi18n.t("...")` | **仍能通过语法解析**，纯语义破坏，测试也未必抓到 | 解析层排除 `TaggedTemplateExpression` + 改写层 `tagGuard` 双保险 |
| 2 | Vue 偏移二次叠加 | `descriptiot("auto...")用户的消息` | 把 script 内的相对偏移又加了一次 | `collectVuePool` 已 rebase，改写侧不得再偏移 |
| 3 | `last + string` | 源码里被写进 `606` 这样的数字 | 数字与字符串相加变成拼接，编译器不报错 | 去掉三元表达式，固定字符串插入 |
| 4 | Vue 属性引号嵌套 | `:title="$t("auto.x")"` 模板解析崩，122 个文件被拦 | 双引号套双引号 | `$t` 用单引号构造 |
| 5 | hooks 注入到非组件 | 在 `onSuccess` 回调里 `const t = useT()` | 违反 hooks 规则，运行时崩溃 | 只认"含 JSX 的函数"为组件 |
| 6 | hook 重复注入 | 同一组件注入多次 | 编译报重复声明 | 按 body 起点去重 |
| 7 | **BOM/CRLF 偏移漂移** | `message.errori18n.t(...)')` | 解析器剥 BOM、改写器没剥，全部偏移差 1 | 统一读取口径 + 写回时还原 BOM/CRLF + `literalShapeGuard` 兜底 |

> 教训一句话：**"能通过 parser"和"改对了"是两件事。** 七个 bug 里只有 1 个（#4）被语法闸抓住，其余全部靠"重解析 + 结构自检 + 人工抽检"才暴露。这直接支持规划 §6.3 的四道闸设计，也说明**必须再加一道"偏移指纹"闸**（`literalShapeGuard`）。

### 4.4 已知未解决缺陷（写进 backlog，不隐藏）

1. **句子碎片化**：`<a>{owner}</a> 发布在 <a>{href}</a>` 只把"发布在"抽出来。中文尚可，英文语序会崩。→ 需要 JSX 富文本整体建模（`<a>` 作为占位符），不能用纯文本节点切分。
2. **量词/单位单独抽**：`万`、`元`、`{v0}月` 被单独成键。→ 需要 ICU MessageFormat 或"数字+单位"合成规则。
3. **HTML 藏在字符串里**：`` `<g>${x}</g>` `` 这类被翻译（0.1%）。→ 需加 markup 检测。
4. **错误消息/API payload** 被翻译（`throw new Error(t(...))`）：技术上合法，产品上应默认归入"低优先级"，避免把后端错误文案塞进 UI 词条。

## 5. H3 性能：大幅达标

| 指标 | 预算 | 实测（vben，1495 文件） |
|---|---|---|
| 全量扫描（冷） | 3k 文件 < 30s | **1.02s**（1471 文件/s） |
| 全量扫描（热） | — | 0.72–0.77s（1954–2067 文件/s） |
| 单文件 p50 | < 80ms | 0.30–0.41ms |
| 单文件 p95 | — | 1.25–1.78ms |
| 单文件 max | — | 30ms（超大 SVG 组件） |
| 改写（含逐文件 TS 语法校验） | — | 1.84s / 261 文件 / 2351 处 |
| 峰值内存 | 未定 | **RSS 292MB / heap 159MB** |

两点注意：
- **内存是隐藏成本**：1495 文件就吃到 292MB，因为全量 AST 都留在堆里。真实扩展必须按文件流式处理 + worker 回收，否则 1 万文件项目会打爆。
- 改写耗时 1.84s 里大头是 `ts.transpileModule` 语法校验（每文件一次）。可改为"只对改动文件 + 采样校验"。

## 6. H4 适配器成本：部分验证

- 代码量：`parse.mjs` 423 行、`detect.mjs` 85 行、`codemod.mjs` 441 行。其中 Vue 专属约 110 行、React/TSX 专属约 130 行。
- 两个框架在同一会话内从零跑通，说明核心抽象（候选池 + 打分 + 改写计划）是成立的；但**迭代成本主要在 bug 修复而非新框架接入**（七个 bug 里 5 个与具体框架无关）。
- **H4 的 3 人日门槛无法在本会话确认**：需要真正接第三个框架（建议 Svelte 或 Vue2 Options API）才能测量。当前证据只能支持"边际成本在下降"。

## 7. H5 可用性：未验证

原方案要求"80% 用户无协助完成一次提取"。本会话没有用户可测，**这一项保持未知**。建议在 M1 原型出来后做 8–10 人的任务测试，脚本：
1. 打开一个含硬编码的项目 → 2. 预览候选 → 3. 取消勾选 3 条误报 → 4. 执行改写 → 5. 找到"撤销" → 6. 导出词条。
观察点：是否有人直接点"全选应用"（→ 说明默认信任度设计失败）。

## 8. Go / No-Go

### 判定：**GO（条件式）**

| 假设 | 门槛 | 实测 | 判定 |
|---|---|---|---|
| H1 检测 | P≥0.90, R≥0.60 | 0.55 阈值：91.3 / 82.3 | ✅ |
| H2 改写 | 语法 100%、语义缺陷 ≤5% | 语法 100%、缺陷 3.75% | ✅（余量薄） |
| H3 性能 | 3k<30s、单文件<80ms | 1.02s/1.5k、p95 1.78ms | ✅ |
| H4 适配器 | 第 3 个 ≤3 人日 | 未测（2 个已通） | ⚠️ 未验证 |
| H5 可用性 | 80% 无协助完成 | 未测 | ⚠️ 未验证 |

### 三个前置条件（M1 开工前必须定 → 已定，见 [04-决策记录.md](04-决策记录.md)）

1. **键命名方案**：72.5% 的中文串只能生成 `auto.c8aefc2` 这种哈希键。这说明"slug 化"对中文项目基本无效——必须默认走 **AI 命名（主）+ 拼音（兜底）**，并把"可读键"当卖点而不是可选项。
2. **句子级建模**：JSX 富文本必须整体抽取（`<a>` 作为占位符），否则英文语序碎片化会让"翻译后更难看"，这是口碑杀手。
3. **不可改写区（veto 清单）固化**：test/scripts/config/CSS/HTML/console/key-like 六类已在 spike 里验证有效（拦掉 vben 235 条、adp 126 条），要写进产品默认配置，而不是留给用户配。

### 对 01 规划的四处修订

| 规划原文 | 修订 |
|---|---|
| §6.2 检测"阈值 0.5 单开关" | 改**三档**：≥0.55 自动选中 / 0.45–0.55 待确认 / <0.45 隐藏。精度断崖证明单阈值会误伤 |
| §6.4 key 命名"slug 优先" | 中文项目 slug 命中率仅 27.5%，改为 **AI 命名优先 + 拼音兜底 + 哈希仅作 last resort** |
| §6.3 四道闸 | 补第 5 道 **偏移指纹闸**（literalShapeGuard）与第 6 道 **veto 闸**（不可改写区） |
| §5 性能预算 | 补**内存预算**：单次全量 ≤150MB，超限转流式；worker 池上限按文件数自适应 |
