# 安装与使用

本文只讲"怎么把它装进 VS Code 并用起来"。设计取舍与指标见 [README](../README.md)、[03-Spike结果](03-Spike结果.md)。

---

## 1. 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| VS Code | **≥ 1.80**（实测 1.98.2） | 扩展是 CommonJS 入口；1.94 起 VS Code 才支持 ESM 扩展，但 1.98 仍用 `require()` 加载 `main`，所以固定走 CJS |
| 项目 | 一个**文件夹** | 扫描以工作区为单位；只开单个文件不工作 |
| Node | 不需要 | 运行时依赖已打进 vsix（2.89 MB / 880 个文件） |

装之前先确认版本：`帮助 → 关于`，或命令行 `code --version`。

---

## 2. 安装

### 方式 A：图形界面（推荐，最不容易出错）

1. 打开 VS Code，左侧 **扩展** 视图（`Ctrl+Shift+X`）
2. 点视图右上角的 `···` → **Install from VSIX...**
3. 选择 `packages/vscode/i18n-codemod-0.1.2.vsix`
4. 右下角提示 `Completed installing i18n-codemod extension` 即成功
5. **重新加载窗口**（`Ctrl+Shift+P` → `Developer: Reload Window`）

> 如果 `···` 菜单里没有 "Install from VSIX"：是你的 VS Code 太旧，升级后再装。

### 方式 B：命令行

```powershell
code --install-extension D:\i18n_local_manage\packages\vscode\i18n-codemod-0.1.2.vsix
```

`code` 不在 PATH 时用完整路径，例如：
`C:\Users\<你>\AppData\Local\Programs\Microsoft VS Code\bin\code.cmd`

想覆盖旧版本加 `--force`：

```powershell
code --install-extension <vsix> --force
```

### 方式 C：分发给同事 / 内网

vsix 是单个文件，直接拷给对方，对方按方式 A 或 B 安装即可。**没有 Marketplace 账号也能用**，但自动更新不生效，升级要重新发 vsix。

### 验证装好了

`Ctrl+Shift+P` 输入 `i18n Codemod`，应能看到这 7 条命令：

| 命令 | 用途 |
| --- | --- |
| `i18nCodemod.scan` | 扫描工作区 |
| `i18nCodemod.applyAll` | 全量改写（提取全部） |
| `i18nCodemod.extractFile` | 只改当前文件 |
| `i18nCodemod.previewFile` | 预览当前文件的 diff |
| `i18nCodemod.showReport` | 覆盖率报告 |
| `i18nCodemod.explainString` | 解释某个字符串为什么（没）被提取 |
| `i18nCodemod.clearCache` | 清扫描缓存 |

看不到命令 = 没装成功或版本太低，先看第 7 节排错。

## 3. 第一次使用

1. **打开项目文件夹**（`文件 → 打开文件夹`），不是打开单个文件。
2. 若弹出"是否信任此工作区的作者"，选 **信任**。受限模式下扩展不会改写文件。
3. `Ctrl+Shift+P` → `i18n Codemod: Scan Workspace for Hard-coded Strings`
4. 活动栏出现地球图标，点开是候选列表（按文件分组）；状态栏显示 `$(globe) i18n xx.x%`。

首次扫描 1500 个文件约 1 秒；之后有缓存，改一个文件只重扫该文件。

### 建议先只读一遍，不要急着改

- 树里每条候选的悬停提示列出**打分明细**（`+0.35 CJK`、`-1.0 wrapped`……），先用它确认判定是否符合你的项目习惯。
- 拿不准某条时，用 `Explain Why`（右键 → 或命令 `explainString`）看完整理由。

## 4. 日常流程

```
Scan → 浏览候选 → Preview（可选）→ Extract → 审 diff / 撤销 → Report
```

### 4.1 预览（不改文件）

- 编辑器里打开 `.tsx` / `.vue` 文件，第 0 行有 CodeLens：`Extract N hard-coded strings` / `preview`
- 或命令 `i18nCodemod.previewFile`：并排打开 diff，左侧原文件、右侧改写结果

预览用的是临时 key 注册表（存在扩展的 globalStorage），**不会污染项目的 keys 文件**。

### 4.2 应用

- 单文件：CodeLens 的 `Extract`，或 `i18nCodemod.extractFile`
- 全量：`i18nCodemod.applyAll`，会弹确认框显示"改写 N 个文件、提取 M 条字符串"

改写有两条硬保证：

1. **走编辑器 undo 栈**。一次 apply 是一个 `WorkspaceEdit`，`Ctrl+Z` 整体撤销。
2. **未保存的脏文件会被拦下**，提示先保存，避免覆盖你正在写的代码。

改完之后会重建扫描索引，树和状态栏立即刷新。

### 4.3 复查

`i18nCodemod.showReport` 打开一份 Markdown 报告：

- 总覆盖率、按目录、最差 25 个文件
- catalog 里已无人引用的**死键**
- 报告是普通 Markdown，可以直接贴进 PR 描述

### 4.4 键与词条落在哪

| 产物 | 默认位置 | 配置项 |
| --- | --- | --- |
| 键注册表（冻结） | `out/keys.json` | `i18nCodemod.keysFile` |
| 词条文件 | 不自动写，除非配了目录 | `i18nCodemod.catalogDir` |

键一旦写入就**永远不改**：再次扫描不会给同一句文案发新键，也不会重命名旧键。这是刻意的——键改名会打断翻译平台的记忆库。

## 5. 配置

`设置 → 搜索 i18nCodemod`，或直接编辑 `settings.json`：

```jsonc
{
  // 打分阈值：0.55 是实测精度/召回的平衡点（P 91.3% / R 82.3%）
  "i18nCodemod.threshold": 0.55,

  // 键前缀：最终形如 app.pages.user.register.placeholder.shou-ji-hao
  "i18nCodemod.namespace": "app",

  "i18nCodemod.keysFile": "out/keys.json",

  // 配了才会把原文写进 <dir>/zh-CN.json
  "i18nCodemod.catalogDir": "src/locales",

  // 框架适配：auto 读 package.json（含 apps/* 一层）
  "i18nCodemod.adapter": "auto",

  // 三个 import 别名，留空表示跟随 adapter
  "i18nCodemod.aliasUseT": "",
  "i18nCodemod.aliasI18n": "",
  "i18nCodemod.aliasTrans": "",

  "i18nCodemod.showStatusBar": true,

  // 0 = 不限制；大仓库调试时可设成 500 先看效果
  "i18nCodemod.maxFiles": 0
}
```

### 适配器与别名

| adapter | 识别依据 | `useT` 默认 | 词条目录默认 |
| --- | --- | --- | --- |
| `next-intl` | 依赖里有 `next-intl` | `@/i18n/react` | `messages/en.json` |
| `react-i18next` | `react-i18next` / `i18next` | `@/i18n/react` | `public/locales/en.json` |
| `vue-i18n` | `vue-i18n` | — | `src/locales/zh-CN.json` |
| `generic` | 都没有 | `@/i18n/react` | `locales/en.json` |

识别错了就显式写 `"i18nCodemod.adapter": "vue-i18n"`，显式值永远优先于自动识别。

**改写的 import 必须能在你的项目里解析**。默认的 `@/i18n/react` 只是约定，若你的 `useT` 在 `src/i18n/useT.ts`，就把 `aliasUseT` 改成实际模块路径，否则改完编译报"找不到模块"。

## 6. 与 CLI 的关系

同一套引擎（`packages/core`），扩展是交互入口，CLI 是批量/CI 入口。两边共享同一个 keys 文件，**可以混用**：

```powershell
node packages/cli/dist/index.js scan   <项目>
node packages/cli/dist/index.js apply  <项目> --dry-run
node packages/cli/dist/index.js report <项目> --catalog src/locales/zh-CN.json --min-coverage 80
```

常见组合：本地用扩展逐条审、提交前用 CLI `apply --dry-run` 看总量、CI 里用 `report --min-coverage` 卡住回退。

## 7. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 装完没有命令 | 没重载窗口，或装的是 0.1.0 / 0.1.1 | `Developer: Reload Window`；装 **0.1.2+** |
| 命令找不到：`command 'i18nCodemod.scan' not found` | 0.1.0：打包漏了运行时依赖（`typescript`），激活抛 `ERR_MODULE_NOT_FOUND`；0.1.1：入口是 ESM，VS Code 用 `require()` 加载 `main`，抛 `ERR_REQUIRE_ESM` | 装 **0.1.2**（CommonJS 入口）：Uninstall 旧版 → 装新 vsix → Reload Window |
| 想确认为什么没激活 | — | `帮助 → 切换开发人员工具 → 扩展宿主`，或看日志目录 `%APPDATA%\Code\logs\<时间>\window1\exthost\exthost.log`；0.1.2 还会在 `...\exthost\i18n-codemod.i18n-codemod\activation.log` 留一行 `v0.1.2 node 20.x` |
| `Install from VSIX` 报 `Extension is not compatible` | 同上 | 升级 VS Code |
| 扫描 0 个文件 | 打开的是单文件而不是文件夹；或路径下有 `node_modules` 之外的排除目录 | 打开项目根目录 |
| 候选特别少 | 阈值过高 / 项目以英文为主（英文裸字面量基线分低） | 把 `threshold` 降到 0.5，或先只看 CJK 项目 |
| 全是 CSS 类名 | 英文项目的 Tailwind 串 | 已经过 `code-like`/style veto 拦，仍漏就调阈值 |
| apply 后没有 import | 自定义别名指向不存在的模块；或该文件是"模块级"（用 `i18n.t`，需要 `aliasI18n` 真实存在） | 检查两个 alias 配置 |
| apply 提示 "文件有未保存修改" | 防止覆盖未保存内容 | 先 `Ctrl+S` |
| 改完 git diff 整篇变红 | 行尾混用（CRLF/LF） | 已在写入时归一，若仍出现请提 issue 并附文件片段 |
| 撤销不彻底 | 分多次 apply | 每次 apply 一个编辑单元，逐次 `Ctrl+Z` |
| 键文件被清空 | 只可能出现在早期版本 | 当前版本历史冻结键永不删除；可从 git 恢复 |

### 卸载 / 升级

- 卸载：扩展视图 → 齿轮 → Uninstall
- 升级：`code --install-extension <新版 vsix> --force`
- 卸载**不会**删你项目里的 `out/keys.json` 和词条文件——那是你的代码资产

## 8. 已知限制（会误判或跳过的情况）

| 场景 | 行为 |
| --- | --- |
| Vue 富文本（`<a>` 嵌在句子里） | **尚未支持**，句子可能被拆成碎片；React 侧用 `<Trans>` 已支持 |
| Vue Options API 组件 | 跳过（`options-api-no-scope`），不注入 `useI18n` |
| 测试文件（`__tests__`、`e2e`、`*.test.*`） | 整文件跳过，避免把断言消息搬进词条 |
| 构建脚本（`scripts/`、`*.config.*`） | 跳过 |
| `console.*` 参数 | veto，不改 |
| 模板字符串里的代码拼接 | veto（`code-like`） |
| 条件表达式里的句子（`a ? 'x' : 'y'`） | 不跨条件合并，逐条判定 |
| 纯数字/单位（`{v0}月`） | 不单独抽，留待人工 |
